## 3 主控与控制板之间的串口协议

控制板是 STM32F407，固件只有 hex，没有源码。串口设备 `/dev/rrc`，波特率 1 000 000。

帧格式：`0xAA 0x55 | 功能码 | 数据长度 | 数据 | CRC8`。CRC8 覆盖功能码、数据长度和数据，算法是 CRC-8/MAXIM。厂商 SDK 文件头的注释把长度写在功能码前面，以实际组帧代码为准。

| 功能码 | 用途 | 方向 | 数据 |
|---|---|---|---|
| 0 | 系统 | 板到主控 | 子命令 0x04 后跟 2 字节电池电压（毫伏） |
| 3 | 底盘电机 | 主控到板 | 子命令 0x01，电机个数，每个电机 1 字节序号（从 0 起）加 4 字节浮点转速（转每秒） |
| 5 | 总线舵机 | 双向 | 见下表 |
| 7 | IMU | 板到主控 | 6 个 4 字节浮点：三轴加速度（g）、三轴角速度（度每秒） |
| 1、2、4、6、8、9、10 | 灯、蜂鸣器、PWM 舵机、按键、手柄、航模遥控、屏幕 | | 适配器暂不用 |

总线舵机的子命令：

| 子命令 | 用途 | 数据 |
|---|---|---|
| 0x01 | 写位置 | 2 字节时长（毫秒），舵机个数，每个舵机 1 字节 ID 加 2 字节位置 |
| 0x03 | 停止 | 舵机个数，各舵机 ID |
| 0x05 | 读位置 | 发 ID；应答是 ID、子命令、状态（0 为成功）、2 字节位置 |
| 0x07 | 读电压 | 同上，应答数值 2 字节 |
| 0x09 | 读温度 | 同上，应答数值 1 字节 |
| 0x0B、0x0C | 上力矩、卸力矩 | 发 ID |

要点：

- **没有轮速反馈。** 控制板不上报编码器或电机转速，上报只有电压、按键、IMU、手柄、航模遥控和舵机应答。
- **舵机一问一答。** 每次只能读一个舵机；厂商 SDK 等应答时不设超时，舵机不回就一直卡住。
- **没有力或电流反馈。** 舵机只能读位置、电压、温度、力矩开关状态和几项限位。

本仓库的编解码库在 `rrc_protocol/codec.py`，按上表实现。

## 4 厂商驱动的 ROS 接口

写适配器时要关掉这些节点，这里列出来是为了对照。

| 节点 | 订阅 | 发布和服务 |
|---|---|---|
| `ros_robot_controller`（串口驱动） | `~/set_motor`（四个轮速）、`~/bus_servo/set_position`、`~/bus_servo/set_state` | `~/imu_raw`、`~/battery`、`~/joy`、`~/button`；服务 `~/bus_servo/get_state` |
| 里程计节点 | `controller/cmd_vel`、`cmd_vel`、`app/cmd_vel` | `odom_raw` |
| `servo_controller` | `servo_controller`（舵机位置）、`joint_controller` | `~/joint_states`、`~/servo_states` |

要点：

- **速度指令没有超时。** 驱动只在收到指令时下发轮速，启动和正常退出时发一次零速，中间不检查指令是否还在来。
- **里程计的平移是指令回填。** 位移由指令速度乘时间算出，不是测出来的。
- **自带的关节轨迹 action 用不了。** 文件里引用了没有导入的名称，按静态阅读一调用就报错。
- **OpenClaw 的抓取节点直接向 `/servo_controller` 发舵机位置。**

## 5 机械臂和底盘参数

| 项目 | 值 |
|---|---|
| 臂关节 | `joint1` 到 `joint5`，舵机 ID 1 到 5 |
| 夹爪 | `r_joint`，舵机 ID 10 |
| 舵机位置原始值 | 0 到 1000，初始 500（夹爪 700）；配置里写的是 min=1000、max=0 |
| 轴距、轮距、轮径 | 0.177 m、0.172 m、0.08 m |
| 麦轮电机顺序 | 1 左前、2 左后、3 右前、4 右后；右侧两轮转速取反 |
| 雷达 | 环境变量 `LIDAR_TYPE=SCLIDAR`，硬件资料里是 COIN-D6 单线雷达 |
| 深度相机 | 光鉴 Aurora 930；ROS 2 驱动是二进制安装包，最高只到 Humble |
| 电池 | 11.1 V，6000 mAh；低于约 10 V 蜂鸣器报警 |

## 6 待实机核对

1. JetPack 和 L4T 版本，内存和固态盘容量。
2. 车上的代码与源码包是否一致。
3. 已启用的服务和监听的端口，OpenClaw 是否自启。
4. 串口实际收发的报文是否与第 3 节一致，IMU 的单位，电压和温度的单位。
5. 断连后轮子停不停，各种断法分别如何。
6. 舵机读一次位置要多久，6 个舵机读一轮要多久。
7. 舵机原始值 0 到 1000 对应的实际转角范围和方向。
8. 车上有没有 Docker，Ollama 的版本和已装的模型。
